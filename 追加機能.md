# Supabase 移行計画

## 背景・目的

現状は localStorage のみでデータ保存 → シングルデバイス限定。
Supabase に移行することで:
- 複数デバイス（スマホ・PC・タブレット）間でリアルタイム同期
- 家族（夫婦）で同じデータを共有・共同編集
- Magic Link によるパスワードレス認証（client-side PIN より安全）
- データバックアップ・復元が不要に

## フェーズ構成

| フェーズ | 内容 | 目安 |
|---------|------|------|
| Phase 1 | Supabase プロジェクト作成・DB スキーマ設計・RLS 設定 | 1日 |
| Phase 2 | Next.js 側 Supabase クライアント実装・Magic Link 認証 | 1日 |
| Phase 3 | Repository 層実装・localStorage → Supabase 移行スクリプト | 2日 |
| Phase 4 | Realtime 同期・テスト・Vercel 環境変数設定・デプロイ | 1日 |

## 必要パッケージ

```bash
npm install @supabase/supabase-js@^2.49 @supabase/ssr@^0.5
npm install -D supabase
```

注意: `@supabase/auth-helpers-nextjs` は非推奨。必ず `@supabase/ssr` を使うこと。

## RLS ポリシー（世帯単位のアクセス制御）

```sql
-- ヘルパー関数
create or replace function my_household_id()
returns uuid language sql security definer
as $$ select household_id from profiles where id = auth.uid() $$;

-- 各テーブルに同じパターンを適用（monthly_records を例に）
alter table monthly_records enable row level security;

create policy "household members only" on monthly_records
  for all using (household_id = my_household_id());
```

## Phase 1: Supabase クライアント実装

```ts
// app/lib/supabase/client.ts
import { createBrowserClient } from "@supabase/ssr";
export const supabase = createBrowserClient(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!
);
```

```ts
// app/lib/supabase/server.ts
import { createServerClient } from "@supabase/ssr";
import { cookies } from "next/headers";
export function createClient() {
  const cookieStore = cookies();
  return createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() { return cookieStore.getAll(); },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value, options }) =>
            cookieStore.set(name, value, options)
          );
        },
      },
    }
  );
}
```

## Phase 2: Magic Link 認証フロー

1. ユーザーがメールアドレスを入力
2. `supabase.auth.signInWithOtp({ email })` を呼ぶ
3. メールリンクをクリック → `/auth/callback` へリダイレクト
4. callback で `exchangeCodeForSession()` を実行
5. profiles テーブルに household_id がなければ household を新規作成
6. パートナーを招待する場合: invite_code をメールで共有 → 相手が入力して同じ household_id に紐付け

```ts
// app/login/page.tsx の核心部分
const { error } = await supabase.auth.signInWithOtp({
  email,
  options: { emailRedirectTo: `${location.origin}/auth/callback` }
});
```

```ts
// app/auth/callback/route.ts
export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const code = searchParams.get("code");
  if (code) {
    const supabase = createClient();
    await supabase.auth.exchangeCodeForSession(code);
  }
  return NextResponse.redirect(new URL("/", request.url));
}
```

## Phase 3: localStorage → Supabase 移行スクリプト

```ts
// app/lib/supabase/migrate.ts
export async function migrateLocalStorageToSupabase(householdId: string) {
  const raw = localStorage.getItem("asset-journey-v1");
  if (!raw) return;
  const state = JSON.parse(raw);

  // 各テーブルにバルクインサート
  await supabase.from("monthly_records").insert(
    state.monthly.map((r: MonthlyRecord) => ({ ...r, household_id: householdId }))
  );
  // ... 他テーブルも同様

  // 完了後 localStorage を削除
  localStorage.removeItem("asset-journey-v1");
}
```

## Phase 4: Realtime 同期

```ts
// app/lib/supabase/useAppState.ts の核心部分
useEffect(() => {
  const channel = supabase
    .channel("asset-changes")
    .on("postgres_changes",
      { event: "*", schema: "public", table: "monthly_records",
        filter: `household_id=eq.${householdId}` },
      () => refetch()  // 変更検知で再フェッチ
    )
    .subscribe();
  return () => { supabase.removeChannel(channel); };
}, [householdId]);
```

## 移行時の注意点（Gotchas）

1. **`@supabase/auth-helpers-nextjs` は非推奨** → 必ず `@supabase/ssr` を使う
2. **cookies は `getAll/setAll`** で実装（`get/set/remove` 個別は型エラー）
3. **RLS INSERT ブロック問題**: プロフィール作成前は household_id が null → `service_role_key` を使うサーバーアクションで household を先に作成
4. **Realtime は self broadcast 無効**: 自分の変更は onchange が発火しない → 楽観的更新で対応
5. **id の型**: localStorage は `Date.now().toString()` の文字列 ID → Supabase は UUID → 移行時に新規 UUID を生成してマッピング
6. **カラム名**: TypeScript は camelCase / DB は snake_case → repository 層で変換
7. **Edge Runtime と cookies**: Next.js の `cookies()` は Server Component / Route Handler でのみ使用可
8. **invite_code の有効期限**: 無制限だとセキュリティリスク → 作成から24時間で無効化するか、使用済みフラグを立てること

## 完了後の状態

- client-side PIN 削除 → Magic Link 認証に完全移行
- localStorage は移行後に削除（または fallback として保持）
- page.tsx の `AppState` 管理を `useAppState.ts` hook に移動
- proxy.ts は session refresh 専用として復活（Edge Runtime で Cookie 更新のみ）
